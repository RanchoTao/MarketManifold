# 项目分工与时间规划

> 当前仓库未包含真实成员姓名和学号，以下使用“成员A/B/C”占位。答辩前必须替换为真实信息；不要在未确认前编造姓名。

## 1. 成员分工表

| 成员 | 角色 | 负责模块 | 具体任务 | 交付物 |
| --- | --- | --- | --- | --- |
| 成员A | 数据负责人 | 数据来源、数据范围、数据清洗 | 确认标普500股票池口径，记录真实数据来源和下载日期，维护 `data/raw/` 目录说明，检查缺失值、异常值、重复值和字段一致性 | 数据来源说明、字段字典、清洗规则、`data/processed/market_snapshots.csv` |
| 成员B | 算法负责人 | 特征工程、聚类建模、评价指标 | 维护滚动窗口特征，完成标准化、多算法聚类、K 值对比、Silhouette/DBI/CH/SSE 评价和结果复现 | `src/dynamic_market_regime.py`、`results/metrics.csv`、`results/figures/k_metrics.svg` |
| 成员C | 展示负责人 | 可视化、画像解释、现场展示 | 整理 PCA/t-SNE、雷达图/柱状图、状态时间轴、前端看板和答辩讲稿，确保离线展示可用 | `results/cluster_profiles.md`、`results/figures/`、`docs/presentation_outline.md`、前端演示 |

## 2. 时间节点

| 时间 | 阶段 | 主要任务 | 验收标准 | 负责人 |
| --- | --- | --- | --- | --- |
| 第1周 | 数据范围确认 | 确定数据源、样本规模、股票池、时间范围、字段含义和是否使用复权价格 | 能清楚回答“数据从哪里来、覆盖哪些股票、时间范围是什么、为什么不提交大型原始数据” | 成员A |
| 第2周 | 数据清洗与特征工程 | 处理缺失值、异常值、重复值，生成滚动窗口市场快照 | 产出 `data/processed/market_snapshots.csv`，字段解释与 README 一致 | 成员A、成员B |
| 第3周 | 聚类实验 | 对 K=2 到 K=6 运行 KMeans、层次聚类、GMM 风格模型，输出 Silhouette、DBI、CH、SSE | 生成 `results/metrics.csv` 和 `results/figures/k_metrics.svg` | 成员B |
| 第4周 | 结果解释与可视化 | 给每个状态命名，生成 PCA/t-SNE 散点图、雷达图/柱状图、画像汇总表 | 产出 `results/cluster_profiles.md`、`cluster_profile_summary.csv` 和 `results/figures/` | 成员B、成员C |
| 答辩前3天 | 彩排与修正 | 按答辩提纲完整演示，准备老师追问，检查前端和离线图 | 演示流程不依赖临时联网；每个指标和状态命名都能解释 | 全体 |
| 答辩当天 | 现场展示 | 展示研究动机、数据、方法、指标、画像、应用价值和局限 | 在规定时间内完成讲解，并能解释数据范围、评价方法和分工 | 全体 |

## 4. 风险与应对措施

| 风险 | 影响 | 应对措施 | 负责人 |
| --- | --- | --- | --- |
| 真实原始数据缺失 | 老师追问真实结论时说服力不足 | 明确说明模拟数据兜底；答辩前尽量补充真实复权价格和下载记录 | 成员A |
| 原始数据过大 | GitHub 仓库臃肿或违反数据授权 | 大型数据只本地保存，仓库提交 `data/raw/README.md` 和处理后小文件 | 成员A |
| K 值指标不一致 | 难以说明最终模型选择 | 同时展示 Silhouette、DBI、CH、SSE，并解释业务可读性 | 成员B |
| 聚类命名主观 | 画像被质疑 | 用簇均值、雷达图、PCA 图和典型时间窗口支撑命名 | 成员B、成员C |
| 前端现场失败 | 展示中断 | 提前运行 `npm run build`；准备 `results/figures/` 静态图作为备份 | 成员C |
| 成员信息缺失 | 分工不完整 | 答辩前替换成员A/B/C为真实姓名、学号和实际贡献 | 全体 |
