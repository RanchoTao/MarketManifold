# 项目分工与时间规划

> 当前仓库未包含真实成员信息，以下使用“成员A/B/C”占位。答辩前请替换为真实姓名和学号。

## 1. 成员分工表

| 成员 | 角色 | 负责模块 | 具体任务 | 交付物 |
| --- | --- | --- | --- | --- |
| 成员A | 数据负责人 | 数据来源、数据范围、数据清洗 | 明确标普500成分股口径，记录原始数据来源和采集时间，检查缺失值、异常值、重复值 | 数据来源说明、字段字典、清洗报告、`data/processed/sp500_features.csv` |
| 成员B | 算法负责人 | 特征工程、聚类建模、评价指标 | 设计收益、波动、动量、回撤等特征，完成标准化、KMeans、K值对比和指标解释 | `src/market_clustering.py`、`results/metrics.csv`、评价图 |
| 成员C | 展示负责人 | 前端可视化、画像解释、答辩材料 | 维护 React 看板，整理聚类画像，准备现场演示路径和答辩讲稿 | 前端页面、`results/cluster_profiles.md`、`docs/presentation_outline.md` |

## 2. 时间节点

| 时间 | 阶段 | 主要任务 | 验收标准 |
| --- | --- | --- | --- |
| 第1周 | 数据范围确认 | 确定数据源、样本范围、时间窗口和字段含义 | 能清楚回答“数据从哪里来、覆盖哪些股票、时间范围是什么” |
| 第2周 | 数据清洗与特征工程 | 处理缺失值、异常值、重复值，生成聚类特征 | 产出可复现特征表和字段说明 |
| 第3周 | 聚类实验 | 对 K=2 到 K=12 运行实验，输出 Silhouette、DBI、CH、SSE | 生成 `results/metrics.csv` 和 K 值评价图 |
| 第4周 | 结果解释与可视化 | 给每个聚类命名，生成 PCA 散点图、核心特征图和画像表 | 产出 `cluster_profiles.md`、图表和前端演示页面 |
| 答辩前3天 | 彩排与修正 | 按答辩提纲完整演示，准备老师追问 | 演示过程不依赖临时联网，关键问题有回答 |
| 答辩当天 | 现场展示 | 展示研究动机、数据、方法、指标、画像和应用价值 | 在规定时间内完成讲解并能解释结果 |

## 4. 风险与应对措施

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 原始数据来源不明确 | 老师追问时难以解释复现性 | 答辩前补充数据来源、下载日期、采集脚本或数据截图 |
| 时间窗口不精确 | 特征含义不够严谨 | 明确 1 年和 6 个月回看窗口的起止日期 |
| K 值指标不一致 | 难以说明最终选择 | 同时解释指标最优、业务可读性和前端展示粒度 |
| 聚类命名主观 | 结果解释可能被质疑 | 用各簇均值、代表股票和图表支撑命名 |
| 现场网络不稳定 | 前端或依赖无法加载 | 提前运行 `npm run build`，准备本地截图和 `results/` 静态图 |
| 成员信息缺失 | 分工不完整 | 答辩前用真实姓名替换成员A/B/C |
