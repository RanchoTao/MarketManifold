# 《基于动态网络与聚类分析的标普500市场结构演化研究》答辩提纲

> 使用方式：每页包含标题、核心内容、建议配图和讲稿要点。现场展示优先使用 `results/figures/` 中的 SVG 图；若前端环境稳定，可切换到 React 看板演示。

## 第1页：研究背景

- **标题**：为什么要研究市场结构演化？
- **核心内容**：标普500不是静态股票集合，而是由收益、风险、行业分化和相关网络共同构成的动态系统。
- **建议配图**：市场状态时间轴或相关网络示意图。
- **讲稿要点**：传统股票分类只能回答“哪些股票相似”，本项目进一步回答“市场处于什么结构状态、这种状态如何变化”。

## 第2页：研究问题与课程价值

- **标题**：从项目提案到可复现实验
- **核心内容**：识别市场状态、解释状态差异、分析事件附近状态切换、形成可展示仪表盘。
- **建议配图**：技术路线流程图。
- **讲稿要点**：强调这是无监督数据挖掘任务，核心贡献是把金融时间序列转化为可聚类的市场快照。

## 第3页：数据集介绍

- **标题**：数据来源与样本范围
- **核心内容**：输入文件为 `data/raw/sp500_prices.csv`，字段为 `date,ticker,sector,close`；默认覆盖 2020-01-01 至 2025-06-30。
- **建议配图**：字段表或 `data/processed/market_snapshots.csv` 截图。
- **讲稿要点**：说明真实数据优先，模拟数据兜底；不在仓库中提交大型原始数据。

## 第4页：样本筛选与清洗规则

- **标题**：如何保证样本可比？
- **核心内容**：日期解析、ticker 标准化、价格正数校验、缺失值剔除、重复记录处理、完整股票池过滤。
- **建议配图**：清洗流程图。
- **讲稿要点**：老师若追问复现性，要说明每个窗口使用同一批可用股票，避免成分变化干扰聚类。

## 第5页：滚动窗口设计

- **标题**：把市场拍成连续影片
- **核心内容**：60 个交易日窗口、20 个交易日步长；每个窗口是一条市场快照。
- **建议配图**：窗口滑动示意图或 `regime_timeline.svg`。
- **讲稿要点**：窗口既要足够长以估计相关矩阵，也要足够短以捕捉状态切换。

## 第6页：特征工程一：收益与风险

- **标题**：市场强度与压力特征
- **核心内容**：平均收益、中位收益、收益标准差、年化波动率、最大回撤。
- **建议配图**：核心特征柱状图 `cluster_feature_bar.svg`。
- **讲稿要点**：收益描述方向，波动和回撤描述风险；二者共同区分牛市、调整和危机状态。

## 第7页：特征工程二：行业结构与分化

- **标题**：市场是否由少数行业驱动？
- **核心内容**：行业集中度、行业收益标准差、行业收益极差、科技相对市场收益。
- **建议配图**：雷达图 `cluster_feature_radar.svg`。
- **讲稿要点**：AI 行情等主题行情常体现为科技行业相对收益上升和行业分化增强。

## 第8页：特征工程三：动态相关网络

- **标题**：用网络刻画共同运动
- **核心内容**：窗口内计算个股收益相关矩阵，构造阈值相关网络，提取平均度数、网络密度和聚类系数。
- **建议配图**：`network_structure_latest.svg`。
- **讲稿要点**：危机时期相关性上升，资产间联动增强，传统分散化效果可能下降。

## 第9页：聚类方法设计

- **标题**：多算法发现市场状态
- **核心内容**：KMeans、Agglomerative Clustering、Gaussian Mixture 风格模型，搜索 K=2 至 K=6。
- **建议配图**：算法对比表。
- **讲稿要点**：KMeans 是可解释基准，层次聚类和 GMM 风格模型用于检验结果是否依赖单一算法。

## 第10页：评价指标

- **标题**：如何选择合适的 K？
- **核心内容**：Silhouette 越大越好、Davies-Bouldin 越小越好、Calinski-Harabasz 越大越好、SSE 用于肘部法参考。
- **建议配图**：`k_metrics.svg`。
- **讲稿要点**：不是凭主观感觉选 K，而是先看指标，再结合市场状态解释和展示粒度。

## 第11页：二维可视化结果

- **标题**：聚类是否具有空间可分性？
- **核心内容**：PCA 二维散点图和 t-SNE 风格近邻布局。
- **建议配图**：`pca_cluster_scatter.svg`、`tsne_market_state_scatter.svg`。
- **讲稿要点**：二维图不能替代指标，但能帮助观众直观看到不同状态的分离程度和过渡区域。

## 第12页：市场状态画像

- **标题**：从 Cluster 编号到可解释 Regime
- **核心内容**：展示 `results/cluster_profiles.md` 中每个状态的命名、核心特征和典型时间窗口。
- **建议配图**：`cluster_feature_radar.svg` 或画像汇总表。
- **讲稿要点**：不要说 Cluster 0，而要说“危机共振状态”“低波动科技牛市”等可解释名称。

## 第13页：动态演化时间轴

- **标题**：2020–2025 市场状态如何切换？
- **核心内容**：按窗口展示状态序列和相邻窗口转移。
- **建议配图**：`regime_timeline.svg`、`regime_transition_graph.svg`。
- **讲稿要点**：状态不是静态标签，而是随时间演化；这体现了项目相对静态股票聚类的升级。

## 第14页：关键事件分析

- **标题**：重大事件附近是否出现结构变化？
- **核心内容**：COVID 冲击、政策/流动性修复、加息周期、AI 成长行情、后周期正常化。
- **建议配图**：`event_change_analysis.md` 摘要或时间轴事件标记。
- **讲稿要点**：说明事件分析不是预测因果，而是检查聚类状态是否与已知市场阶段相吻合。

## 第15页：前端现场展示

- **标题**：从结果文件到交互式看板
- **核心内容**：展示 React/Vite 页面中的指标卡、市场地图、特征表和图形结果。
- **建议配图**：本地前端页面或静态 SVG 备份。
- **讲稿要点**：如果网络或 npm 环境不稳定，直接打开 `results/figures/` 和 Markdown 结果文件完成离线展示。

## 第16页：应用价值

- **标题**：聚类结果能支持哪些应用？
- **核心内容**：风险监控、市场复盘、组合再平衡、行业轮动识别、投资者教育、推荐系统权重调整。
- **建议配图**：应用场景矩阵。
- **讲稿要点**：本项目不是预测明天涨跌，而是建立可解释的市场状态识别框架。

## 第17页：局限与改进方向

- **标题**：如何继续提升？
- **核心内容**：接入真实复权价格、补充市值权重和成交量、使用真实 GICS 权重、加入 HMM/变点检测、Bootstrap 稳定性检验。
- **建议配图**：未来工作清单。
- **讲稿要点**：主动承认模拟数据兜底和标准库模型的限制，并说明替换真实数据后的路径不变。

## 第18页：总结

- **标题**：核心贡献
- **核心内容**：完成数据、特征、模型、评价、解释、可视化、展示材料的闭环。
- **建议配图**：完整技术路线图。
- **讲稿要点**：用一句话收束：本项目研究的是“市场结构如何形成和改变”，不是简单给股票贴标签。
